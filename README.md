账号在两地之间来回登录，风控一直显示一切正常，直到被人改了绑定手机：距离计算用平面近似，跨高纬度误差巨大；距离计算用角度未转弧度，结果量级错；旅行速度用距离除以分钟，单位混用导致阈值失效；缺少时间戳时按零处理，速度恒为零永不触发；速度判定用严格小于，恰好等于阈值被判异常；地区判定用字符串前缀，相邻地区被误判为可信；时区差用整数相减不做跨日归一，负值被当成零；二次验证只在单条规则命中时触发，未做风险聚合；策略校验不检查速度阈值是否合理；批量判定复用上一次位置，后一个事件命中前一个事件的位置。geo/fence.py 是核心，tests/test_fence.py 15个红。要修的是：按上面的顺序把 10 个缺陷逐个修掉。

## 运行方式

在仓库根目录执行：

```
python -m pytest tests -q
```

初始状态下应当得到 `15 failed`，没有 `passed`，也没有 `error`。测试只依赖 pytest，运行过程离线，不使用随机数，时间与时区地理数据全部由测试参数注入。

## 初始状态

- `src/geo/fence.py` 里的 8 个函数全部是桩，函数体只抛出 `NotImplementedError`。
- `tests/test_fence.py` 恰好包含 15 个测试，当前全部失败。
- 其中 10 个测试分别对应 10 个缺陷，另外 5 个是回归测试：同城登录不触发、跨洲短时间登录触发、可信地区放行、时区差跨日正确、两批独立判定与单独判定相同。
- `tests/test_fence.py` 是评测入口，不可修改；修复只能发生在实现文件中。

## 布局与约束

这是 `pyproject.toml` 指定导入路径的 src 布局：`[tool.pytest.ini_options]` 设置 `pythonpath = ["src"]`，因此测试从 `geo.fence` 导入，不需要安装包。实现只使用标准库 `math`、`datetime`、`ipaddress` 以及 pytest，不联网、不读取外部地理数据、不使用随机性。所有时间、坐标、IP 和策略都由调用方传入。
